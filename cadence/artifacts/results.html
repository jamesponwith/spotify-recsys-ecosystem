The idea

Track metadata contains no mood

So the bridge from language to music has to come from somewhere else.

The string Holocene — Bon Iver does not contain the words calm, winter, or driving. No text encoder can extract meaning that is not in the text. This is the reason natural-language music search is hard, and it is not fixed by a bigger embedding model.

But the corpus holds 98,334 playlists that humans named — rainy day, gym, studying, 90s throwbacks, late night drive. Those titles describe how music gets used. Build a track × title-token matrix, factorise its Shifted PPMI, and a phrase and a song land in one space — grounded entirely in human behaviour rather than in a model's guess.

Why factorise rather than train

Levy & Goldberg (2014) showed skip-gram with negative sampling is implicitly factorising a shifted PMI matrix. Doing it explicitly gives the same class of embedding with no epochs, no learning rate, and no sampling noise — a 40-second fit that is bit-for-bit reproducible from a seed. For a system whose evaluation has to be trustworthy, removing a source of run-to-run variance is worth more than the last fraction of a point.

The measurement that changed the design

The first working version shipped only the learned collaborative embedding, and it lost to a plain item-kNN baseline at k=5 — 0.129 against 0.142. The honest reading was that 160 dimensions genuinely lose information exact counts keep. Rather than tune the embedding until it won, exact co-occurrence became its own channel and fusion arbitrates. That took k=5 to 0.178, and the reranker to 0.248.

How it runs

Eight stages, ~100 ms warm

Numbered because it genuinely is a sequence — each stage consumes the last.

  1. 01planFree text → structured intent. Deterministic rules by default (49-entry mood lexicon, ~4 ms, no API key); Claude with structured output optionally.
  2. 02maskHard constraints become a boolean filter over the catalog — explicit, duration, tempo window, avoided artists.
  3. 03retrieveSeven channels answer differently: collaborative embedding, exact co-occurrence, folksonomy embedding, exact tag counts, TF‑IDF lexical, audio‑feature k‑NN, popularity prior.
  4. 04fuseReciprocal rank fusion, because cosine scores, TF‑IDF dot products and damped counts are not on comparable scales.
  5. 05rerankGradient-boosted trees over 30 features. Validation AUC 0.849 against 0.639 for the fusion score alone.
  6. 06selectMMR diversity, per-artist caps, duration targeting. Twenty near-identical songs is a perfect ranking and a bad playlist.
  7. 07sequenceBeam search over an energy arc, Camelot-wheel key compatibility and tempo continuity.
  8. 08explainPer-track reasons grounded in real counts; generated copy scanned against the catalog before it ships.

Domain

A playlist is an arc, not a set

The same twenty tracks in a different order are a different product.

Harmonic mixing, as code

Adjacent tracks in compatible keys sound intentional. Compatibility is the standard Camelot wheel: position ((root×7) mod 12 + 7) mod 12 + 1 walking the circle of fifths, with minor keys placed on their relative major.

From 8B, three moves are cheap — 8A (relative minor), 7B and 9B (a fifth either way). A tritone away costs full price. The sequencer's beam search minimises that cost alongside a tempo term and an energy-curve target.

Tracks missing key or tempo get a neutral cost rather than an imputed one, so sequencing degrades with coverage instead of failing.

The other half of the promise

Constraints are filters, never prompts

A filter cannot be talked out of its job. An instruction can.

Ranking metrics say nothing about whether the delivered playlist honours what was asked. A separate battery of 20 constrained requests runs end to end and checks:

Zero failures. Mood adherence — the gap between the delivered playlist's mean audio feature and what the request implied — lands within 0.05 on a 0–1 scale for five of six dimensions.

Three bugs only real output revealed

None was visible in R-precision. All three were obvious in printed output.

  • A curve conflict. “chill rainy morning” matched both chill (energy 0.32) and morning (curve build), and the implied curve won — producing a playlist that ramped up, ending on Wonderwall at 0.90 energy. An implied curve now has to agree with the energy target or it is dropped.
  • Min-max normalisation hiding the audio term. The reranker emits probabilities with median ~0.002 and max ~0.7. Min-max normalising that leaves nearly everything at zero and a handful at one, so blending audio affinity against it did nothing at any weight. Rank-normalising relevance fixed it: mean energy for a “chill acoustic” request moved from 0.63 to 0.43 against a 0.35 target.
  • Constraint words leaking into the query. “nothing explicit” correctly set the clean filter — and then nothing and explicit, both present in the tag vocabulary, also became query themes and dragged the tag centroid toward unrelated music. Excluding constraint-consumed words cut mean instrumentalness error from 0.221 to 0.130 and energy error from 0.056 to 0.043.

Where it falls down

Honest limitations

  • The explicit filter is best-effort. The flag is known for only 2.76% of the catalog. Known-explicit tracks are removed; unlabelled ones cannot be checked, and the system says so on every affected response. This is not a child-safety control.
  • Era targeting is inferred, not factual. Neither data source carries a release date, so 1990s means “music people file under the 90s”, derived from playlist titles.
  • Diversity is the weak spot. Mean long-tail share is 0.057 — the system draws heavily from the popular head, and the reranker makes that worse while making accuracy better. Measured and reported, not hidden.
  • The k=0 task uses playlist titles as queries, which are tidier than real user input. Evaluation playlists are excluded from the tag matrix so the setup is not circular, but the query distribution is friendlier than production.
  • Many themes dilute each other. The tag channel embeds a query as the centroid of its theme vectors, so a request stacking an activity, a mood, a genre and an era averages five vectors and drifts toward the most generic of them. Weighting identity tags above soft ones is the obvious fix — but the evaluation uses playlist titles, which carry one or two themes, so it would barely register the change. Shipping it unmeasured would be guessing; it needs a multi-constraint query set first.
  • Sequencing quality is unmeasured. Whether the energy arc and harmonic transitions actually sound intentional needs listening tests. That is the real gap in this evaluation.

Reproduce

Every number regenerates from a clean checkout

make venv install          # Python 3.12 + deps
make data                   # MPD + audio features
make all                    # build → splits → train → reranker → eval

cadence play "chill acoustic songs for a rainy sunday, 8 songs"
cadence eval-constraints    # does assembly honour what was asked?
cadence serve               # HTTP API on :8000

Seeded throughout. 6,040 lines of Python, 103 tests, clean ruff and mypy. Five documents cover architecture, evaluation protocol, ten decision records, and the data and model cards — including the decision that was wrong first.
